# v0.1.47 Release Notes

## Conversation performance and continuity

- Limit the mounted conversation DOM to the most recent 80 messages and reveal
  older history in pages without losing the reader's scroll position.
- Keep live event buffers isolated by session so background activity does not
  rebuild the active conversation tree.
- Batch live events per animation frame while preserving their native order.
- Improve the conversation trail and native subagent presentation, including
  effective model labels and clearer delegated activity.

## Project and workspace lifecycle

- Finish project creation independently of optional Forge account detection so
  missing authentication or a slow CLI cannot leave the modal stuck on Creating.
- Apply bounded process timeouts and refresh Forge metadata asynchronously, with
  observable warnings and an explicit retry path.
- Recover idempotently when a workspace was persisted but the create response was
  interrupted, avoiding duplicate or orphaned workspace records.
- Remove DCC sessions, conversations, search rows, delegations, and review data
  when a project is removed, while preserving the root repository and global
  Forge accounts so reopening the path starts cleanly.

## Runtime stability

- Avoid constructing and dropping a nested Tokio runtime while serving session
  history through the HTTP API.
- Refresh desktop workspace and repository caches after background Forge metadata
  updates.
- Make repeated sidecar staging builds replace read-only executable artifacts
  safely instead of failing on a previously generated target.

## Validation before publishing

- Run desktop type checks, the complete desktop test suite, and the production
  desktop build.
- Run Rust formatting, workspace checks, and the complete Rust test suite,
  including the local streamable HTTP MCP fixture.
- Confirm release metadata is `0.1.47` in the root package, sidecar, Cargo, lock,
  and Tauri configuration files.
- Let the release workflow build signed macOS and Linux artifacts, inspect the
  draft release and `latest.json`, then publish only after manual verification.
