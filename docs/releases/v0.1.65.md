# v0.1.65 Release Notes

## Performance and resource retention

- Bound retained session events and release live buffers after history catches
  up, reducing retained data during long conversations.
- Release terminal resources when terminal state is removed.
- Remove completed sidecar response and permission listeners, and reuse
  compiled ANSI cleanup expressions.

## Mobile companion

- Start tasks from the phone with the configured agent/model catalog, optional
  planning, and either an existing workspace or a new isolated branch/worktree.
- Recover task creation after a lost network response without creating another
  task. Preserve partial results if the HTTP service restarts during creation.
- Reconnect after network changes and foreground transitions, refresh persisted
  history, and retain local drafts and snapshots of visited conversations.
- Add an installable PWA with an offline shell, app shortcuts, and explicit
  application updates. Public asset caching excludes API and pairing responses.
- Answer agent questions and inspect per-file patches from the phone.
- Add opt-in encrypted Web Push notifications for completed/interrupted turns
  and pending decisions.
- Accept a configured HTTPS origin in desktop pairing so QR links can open the
  installable companion directly. Improve the mobile composer and keyboard layout.

## Current limits

- Local execution still requires an awake, reachable computer and a running
  HTTP service. Installing the PWA does not move agent execution to the cloud.
- Responses to approvals/questions are handled by the HTTP runtime for tasks
  started through the companion. Forwarding responses to agents running in the
  separate desktop process remains a follow-up architecture change.
- PWA capabilities and push require HTTPS and browser support. Real push delivery
  on a physical phone remains to be verified; browser smoke tests use a mock server.

## Validation before publishing

- Desktop: 120 test files / 693 tests passed; desktop type checks and the
  production frontend build passed.
- Mobile: 7 unit tests, type checks, and the production build passed. Chromium
  smoke tests covered pairing, creation-response loss, offline history/drafts,
  reconnection, agent questions, file patches, and public-cache boundaries.
- Sidecar: 31 tests passed. HTTP/authentication/pairing Rust library tests:
  41 passed, including mobile task recovery, real Git patches, and push storage.
- Run the local MCP release gate and check Rust formatting and release metadata.
- Let the existing release workflow build signed macOS and Linux artifacts and
  create the GitHub draft release for artifact verification and publication.
