# v0.1.67 Release Notes

## Smaller package with user-installed Claude Code

- DCC continues to use the Anthropic Agent SDK, now with the Claude Code CLI
  installed by the user. The app no longer bundles a second Claude Code copy.
  The removed copy occupied approximately 190 MiB in the previous macOS ARM64
  installation; final package and download sizes are measured during release
  validation.
- Install and authenticate Claude Code before selecting the Claude provider.
  DCC reports missing installations and login requirements; it does not download
  a replacement CLI. See the provider prerequisites in the README.
- Preserve PATH precedence and discover standard native installations when
  launched outside a terminal. An explicit CLI path remains authoritative.
- Fix development startup selecting a Node placeholder as the Claude sidecar.
- Check authentication-command support using the CLI version, with the selected
  executable path in errors. The auth check requires Claude Code 2.1.41 or newer;
  integration validation used 2.1.259 with Agent SDK 0.2.126.
- Retain the macOS startup fix from 0.1.66 and the release checks for external
  libraries, signatures, notarization and signed-app launch.

## Validation

- Local MCP release checks passed, covering Rust tests, provider regressions,
  contract and desktop type checks, and frontend MCP tests.
- All 43 sidecar tests passed, including CLI discovery, authentication checks,
  missing installations and rejection of legacy CLIs before issuing auth commands.
- The compiled sidecar passed authenticated MCP integration checks over stdio
  and HTTP with the external native Claude Code 2.1.259.
- Local authentication confirmed the existing macOS login. Manual development
  testing passed task creation, Claude/model selection and prompt execution.
- The 0.1.67 compiled sidecar discovered the native CLI and confirmed authentication
  with only `/usr/bin:/bin` in PATH, without a Node or NVM executable in that PATH.
- Signed release archives still require the CI bundle checks and final installed
  app validation. Development testing does not replace that validation.

## Updating

Versions that open normally can use the in-app updater after publication.
If still on the broken macOS 0.1.65, download the matching archive (`aarch64` for
Apple Silicon, `x64` for Intel) and replace the app in Applications. Preserve
the DCC data directory; a clean installation is not required.
