# v0.1.22 Release Notes

## Highlights

- Added real account-usage visibility for Codex and Claude without adding a
  permanent meter beside the composer send button.
- Added a detailed account-usage area under Settings > Providers and a compact
  summary inside the existing provider/model menu.
- Added actionable composer warnings only when an account is close to its
  limit: yellow at 20% remaining and red at 5% remaining or when exhausted.

## Provider Account Usage

- Codex now reads structured account rate-limit windows directly from the
  app-server protocol, including remaining percentage and reset time.
- Claude now consumes structured rate-limit events from the Agent SDK and
  keeps the latest usage snapshot isolated by provider runtime.
- Claude shows an explicit waiting state until the SDK reports usage after
  provider activity instead of fabricating or scraping a value.
- Unsupported providers remain hidden from account-usage surfaces until they
  expose a reliable structured source.

## Composer And Settings

- Usage values are always labeled as `remaining` to avoid ambiguity between
  provider APIs that report used percentage and CLIs that show remaining
  percentage.
- Removed the synthetic session-context estimate based on turn and checkpoint
  counts.
- Preserved the calm composer layout by showing account usage beside Send only
  when the user may need to take action.
- Replaced the internal T3 reference in provider settings with the neutral
  `Isolated runtime` label.

## Validation Before Publishing

- Run desktop type checks: `yarn workspace @dcc/desktop typecheck`
- Run the complete desktop test suite: `yarn workspace @dcc/desktop test`
- Build the production desktop frontend: `yarn workspace @dcc/desktop build`
- Check the Tauri crate: `cargo check --manifest-path src-tauri/Cargo.toml`
- Confirm release metadata is `0.1.22` in `package.json`,
  `sidecar/package.json`, `sidecar/src/index.mjs`, `src-tauri/Cargo.toml`, and
  `src-tauri/tauri.conf.json`.
