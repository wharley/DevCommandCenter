# v0.1.95 Release Notes

## More than one account per provider

- Claude and Codex can now hold named accounts besides the system login —
  for example a personal and a work account. Add them in Settings →
  Providers → Accounts and click **Sign in**: DCC opens the provider's
  sign-in page in your browser and the row shows the email and plan once
  you authorize. The terminal command stays as an alternative.
- Each Claude account keeps its own login, history and `.claude.json`, and
  starts with links to your `CLAUDE.md`, settings, skills, agents, commands,
  hooks and plugins. A Codex account keeps only its own login over your
  shared `~/.codex`, so config, skills and conversations are the same.
- Pick the account in the model picker's **Account** row; the composer
  button names a non-default account. New tasks use the account picked for
  their provider, and a conversation stays on the account it started with.
  A delegated child on the same provider inherits its parent's account.
- Claude now runs an account with `CLAUDE_CONFIG_DIR` instead of a swapped
  `HOME`, so the agent keeps your git, ssh and gh logins. Usage is read and
  cached per account.
- The Codex app-server now honors the shadow home set in Settings, which it
  ignored before.

## Continue on another account when a limit runs out

- The usage-limit notice offers **Continue with <account>** for each other
  account of the task's provider, with how much of its plan is left. Codex
  continues the same conversation; Claude starts a new one carrying a
  summary of the task so far. Automatic resume never switches accounts.
- The stopped turn's notice says which account the task continued on.
- A lapsed Claude token (typical on the first use of the day) now shows
  usage as waiting for activity instead of an error.

## Settings → Providers, redone

- A list of providers with one line of status (off, unavailable, needs
  attention, N accounts, ready) and, beside it, everything about the chosen
  one: its switch and health, its accounts with a bar of how much of each
  plan is left (open a row for its usage windows and reset credits), the
  model new tasks start with, and an **Advanced** disclosure for the
  executable, homes and subagent limit.

## Browser and computer use ask once per task

- One approval covers the task. A task in Full access, or one you already
  allowed, opens the DCC Browser without asking while that task is on
  screen; it still asks when you are looking at another task. An approved
  Browser grant renews while the agent uses it.
- Computer use re-arms the apps you approved for the task when its grant
  lapses. Full access does not skip it, since it moves your cursor.
- Requests now wait five minutes instead of 45 seconds, Escape or a click
  outside no longer denies, and when DCC is not in front the Dock icon
  bounces and a system notification names the request. Turning agent
  control off ends the task's approval.

## Tasks across projects and folders

- New task has one flow: the project you pick is the primary, and "Also in
  this task" brings its linked folders, other projects as chips and folders
  without Git as context.
- A project can link other folders in "Edit project" (up to 8). Git folders
  join every new task as projects; folders without Git ride along as context
  the agent can read, listed on the task's identity card.
- A multi-project task can run directly in the checkouts (Worktree off), and
  Undo and "Edit from here" cover every project of a turn.

## Timeline

- The agent's plan reads as a checklist with its progress ("6/12 · Running
  the tests") for Claude and Codex; Codex plans reach the timeline now.

## Fixes

- ai-memory: development and installed sidecars no longer share a server by
  accident, and a shared server's version is shown.

- Rust workspace and app tests passed (over 1,300 tests) except the known
  `dcc-mcp-fixture` tool-list failure, unchanged since v0.1.94 and unrelated

- Claude Code 2.1.293: account keychain naming and the `BROWSER` sign-in
