# v0.1.52 Release Notes

## Reviewed multi-project delivery

- Add a separate editable commit subject and body for every changed repository
  in a multi-project task.
- Generate each suggestion from that repository's staged Git snapshot using the
  provider and model selected in DCC, with the existing deterministic fallback
  when provider generation is unavailable.
- Distinguish repositories that need a commit and push, only a push, only a pull
  request, or require attention before delivery.

## Delivery safety

- Bind every reviewed commit to the exact staged fingerprint and branch that
  were shown in the confirmation dialog.
- Re-run required `beforePush` checks and stage all changes immediately before
  committing; block the affected repository if checks or concurrent edits
  changed the reviewed snapshot.
- Deliver only the workspace identities included in the prepared review, so a
  repository that changes later cannot enter the operation silently.
- Preserve sequential delivery and per-repository results because Git cannot
  provide a transaction across multiple repositories.

## Validation before publishing

- Run desktop type checks, all 466 desktop tests, and the production desktop
  build.
- Exercise preparation, edited messages, push-only repositories, missing
  reviews, duplicate workspace identities, and stale fingerprint rejection.
- Confirm release metadata is `0.1.52` in the root package, sidecar, Cargo, lock,
  and Tauri configuration files.
- Let the release workflow build signed macOS and Linux artifacts and publish
  updater metadata.
