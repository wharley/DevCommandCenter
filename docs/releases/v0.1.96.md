# v0.1.96 Release Notes

## Agents propose tasks; the parent coordinates

- An agent can now propose a piece of work as its own task: a separate,
  long-lived conversation in the same workspace. It shows as a card in the
  parent's thread with **Start**, **Edit brief** and **Dismiss**; nothing runs
  until you start it. When a reply names the next phase of a plan, the agent
  proposes it instead of only describing it; small follow-ups stay a sentence.
- A task runs on the parent's provider by default and stays open across
  turns. Each time it ends a turn the parent hears back with a short status
  and where every task of the plan stands, so you can follow the whole plan
  from the parent without opening each task. Turns you drive inside a task
  update it without waking the parent. The parent sends a task follow-ups
  only from a turn you started.
- A task that edits works where its parent works: in the same checkout when
  the parent runs without a worktree, in its own worktree otherwise. It runs
  with the parent's access, so a parent in Full access does not stop the
  task for every write. On the parent's card, an idle worktree task with
  changes offers **Review and apply**; **Close task** ends the others.
- In the sidebar, tasks hang under their workspace with a guide line: green
  while working, grey while open but stopped, amber when they need you
  (proposed, an approval or a question, edits to review). A task stopped on
  an approval also says so on the parent's card, with a button to it, and
  **Needs you** opens the conversation that waits. Opening a workspace lands
  on its own conversation, and clicking it from inside a task goes back to
  the parent.
- On the phone, a proposal arrives as a notification and shows under
  **Precisa de você**, at the end of the parent's thread and in the badge,
  with Start and Dismiss. The first answer wins, on the phone or the Mac.
- Safeguards: a turn DCC started (a result coming back) cannot delegate or
  start work on its own, one turn delegates at most six times and proposes
  at most three tasks, a task cannot propose tasks, and a proposal nobody
  started is withdrawn after a week. Claude, Codex and Cursor can propose.

## Files and changes in the code column

- The project's files sit in a column beside the tasks sidebar
  (Cmd/Ctrl+Shift+E). A file opens as a tab next to the Chat tab, and the
  conversation stays underneath; Escape goes back to it.
- The file tree shows new files before they are staged, colors changed
  files by git status, starts collapsed and moves with the arrow keys.
  Right-click a file to mention it in the chat or copy its path, or drag it
  onto the composer.
- A **Changes** tab lists the task's changes; a change opens its diff as a
  tab on the stage. The Inspector's Git review (recap, delivery, PR review,
  pipeline, CodeRabbit) moved there, and its activity and context became a
  **Session** tab. The right-side panel is gone; Cmd/Ctrl+Shift+G opens
  Changes.
- The editor keeps each open file's draft, caret and undo history when you
  switch tabs. Enter keeps the indentation and Tab types the project's indent,
  read from `.editorconfig` or the file itself.

## Providers report problems before you send

- The model picker only offers providers that can start; the ones left out
  are counted under the list, with a link to set them up. The one already in
  use stays visible with its reason.
- Grok, Gemini and Codex now report a missing or expired sign-in in their
  health check instead of failing after you send. Settings has **Check
  again**, and the picker rechecks when it opens.
- A provider that still cannot start leaves an interrupted turn that says
  why, in your language, with Retry and **Set up provider**, instead of a
  toast that disappears.
- A broken executable path is caught before sending and shows as "Needs
  setup"; resetting it in Settings now actually clears it from the
  conversation.
- Settings speaks your language for known providers and models, and signed
  out, missing runtime and not installed all read "Needs setup".
- The picker names the open provider tab, keeps its height, and a new task
  starts on the model last picked in that project.

## Delivery without a remote

- A task in a repository without a remote commits locally: the Dock and the
  Inspector say **Commit**, and push and pull request stay disabled.
  Sidebar, review and composer all name the branch the same way
  ("main · no branch").
- The commit dialog stages every change when nothing is staged, so its
  message fills in and committing is one click; cancelling unstages only
  what it staged.
- The Dock's commit message comes from the staged files, never from a model.
- The create-PR dialog names where the pull request goes, and explains how
  to connect a forge when there is none.

## Fixes

- The sidebar no longer jumps back to the selected task while you scroll,
  and "needs you" no longer moves rows under the pointer. The running count
  leaves out tasks waiting on you.
- Antigravity under Approve for me no longer asks again for a command you
  already allowed, and its Settings badge describes the configured
  executable.
- Local `file://` links in the timeline show as links instead of
  "[blocked]".
- New task's "Open another project…" leads the list and opens the folder
  picker with nothing preselected.
