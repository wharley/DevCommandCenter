# v0.1.36 Release Notes

## MCP Integrations Preview

- Connect remote HTTP MCP servers or local command-based servers directly in
  DCC, without editing provider-owned configuration files.
- Bind integrations to a session, project, or every project and let DCC attach
  them only to provider runtimes with an explicit compatible bridge.
- Claude Code and Codex now negotiate DCC-managed MCP integrations when a
  session starts, with live connection status and discovered tool inventory in
  Settings.
- Remote OAuth authorization is started automatically when a turn needs it.
  DCC preserves the original prompt across browser authorization and resumes
  the provider flow after the grant is available.
- OAuth grants and integration credentials are stored in the operating
  system's credential store. SQLite contains only opaque references and
  non-secret integration metadata.

## Safety and Control

- New command integrations require an explicit trust decision over the
  executable, arguments, working directory, and definition fingerprint.
- Every discovered tool can be set to **Ask**, **Allow**, or **Deny**. Unknown
  tools default to **Ask**, and server-provided read-only or destructive
  annotations remain untrusted informational hints.
- Runtime evidence distinguishes configured, connecting, connected, and failed
  states instead of presenting configuration alone as a successful connection.
- OAuth grants can be disconnected independently from integration definitions,
  and disabling or removing a definition does not modify provider-owned MCP
  configuration.
- Tool policies are collapsed by default in Settings so large servers remain
  practical to review without losing access to individual controls.

## Provider Compatibility

- Claude Code and Codex are the supported providers for this preview.
- Both bridges passed the shared stdio and Streamable HTTP conformance harness.
- A real ClickUp remote OAuth integration was validated read-only through both
  Claude Code and Codex on macOS, including authorization, reuse of the grant
  in a new session, disconnect, reconnect, and automatic preflight.
- Cursor remains unverified for DCC-managed MCP projection. Gemini, Grok, and
  Droid remain unsupported until their runtimes expose the ownership and
  permission evidence required by DCC.
- Linux packages are produced by the release pipeline. The native
  OAuth/credential-store smoke for this preview was performed on macOS, so
  Linux feedback remains welcome without implying unrecorded platform
  validation.

## Workspace Fix

- Workspace cards now keep an available recap visible when setup is also
  pending. The setup-pending state is shown only when no recap exists.

## Validation Before Publishing

- Run the fork-safe local MCP gate:
  `yarn test:mcp:release-local`
- Run desktop type checks:
  `yarn workspace @dcc/desktop typecheck`
- Run the complete desktop test suite:
  `yarn workspace @dcc/desktop test`
- Run the Rust workspace tests:
  `cargo test --workspace`
- Check the Tauri crate:
  `cargo check --manifest-path src-tauri/Cargo.toml`
- Confirm release metadata is `0.1.36` in `package.json`,
  `sidecar/package.json`, `sidecar/src/index.mjs`, `src-tauri/Cargo.toml`, and
  `src-tauri/tauri.conf.json`.
- Let the release workflow build, sign, and package Linux and macOS artifacts;
  review every draft asset and `latest.json` before publishing.
