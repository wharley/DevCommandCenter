# v0.1.98 Release Notes

## The phone sees what really runs

- The phone's home showed fewer running tasks than the desktop (0 or 1 while
  the sidebar said 2). It rebuilt "running" by itself from the full history
  of up to 20 sessions — megabytes over the relay on every turn — and read a
  history that took too long as an idle agent. Now the desktop says what
  runs, with the same rule as its sidebar: one row per task.
- `GET /api/v1/mobile/attention` also returns the running tasks, the open
  permission and question requests (answered inline without reading
  histories) and a `snapshotId`. Sent back as `?after=`, it answers
  `{ "unchanged": true }` while nothing moved, so the phone checks every few
  seconds for a few bytes.
- A task enters or leaves **Running** on the phone as soon as its turn starts
  or ends, and a failed read keeps what was on screen instead of emptying it.

## Faster over the relay

- `GET /api/v1/events/stream?kinds=lifecycle` sends only the events that
  change what a task is doing — never streamed text or tool output. The
  phone's home and banners use it; before, every token of every running
  agent crossed the relay three times.
- A request the phone stops waiting for is cancelled on the desktop, so a late
  answer no longer holds up the ones behind it.
- Session summaries keep their folded history until new events arrive, which
  makes the sidebar and the phone's checks cheaper with long sessions.
