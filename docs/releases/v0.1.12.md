# v0.1.12 Release Notes

## Highlights

- Fixed mobile pairing over Tailscale in production builds.
- Bundled and auto-started the mobile HTTP backend used by QR pairing.
- Hardened advertised endpoint selection so unavailable network routes are not
  offered to phones.

## Mobile Pairing

- Included `dccd-http` and the built mobile web app in production release
  bundles, matching the QR flow that opens `http://<desktop>:9876/m/pair`.
- Started `dccd-http` automatically before generating pairing challenges or
  listing phone endpoints, removing the need to launch it manually.
- Bound the HTTP backend to the network listener correctly for LAN and
  Tailscale access.
- Detected Tailscale IPv4 addresses from local network interfaces, using the
  Tailscale CLI only as a fallback/MagicDNS source.
- Filtered unavailable endpoints out of the pairing modal so the QR points only
  to routes the desktop backend is actually serving.

## Validation Before Publishing

- Typecheck the desktop app: `npx tsc -p apps/desktop/tsconfig.json --noEmit`
- Check the Tauri crate: `cargo check --manifest-path src-tauri/Cargo.toml`
- Run focused network discovery tests:
  `cargo test --manifest-path src-tauri/Cargo.toml net_info`
- Build the mobile web app: `yarn workspace @dcc/mobile-web build`
- Confirm release metadata is `0.1.12` in `package.json`,
  `sidecar/package.json`, `sidecar/src/index.mjs`, `src-tauri/Cargo.toml`, and
  `src-tauri/tauri.conf.json`.
