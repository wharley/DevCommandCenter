# v0.3.2 Release Notes

## Tasks side by side: ports and .env

- Each task gets its own block of 10 ports, from 41000 up. Its terminals, the
  `.dcc.toml` tasks it runs and its agents get `DCC_PORT` (the first port of
  the block) and `DCC_WORKSPACE_PATH`, `DCC_ROOT_PATH`, `DCC_WORKSPACE_NAME`,
  `DCC_DEFAULT_BRANCH` and `DCC_WORKSPACE_ID`, named after Conductor's. Use
  `next dev -p $DCC_PORT`, `vite --port $DCC_PORT` or
  `expo start --port $DCC_PORT`, and two tasks of one project serve at the same
  time.
- A new worktree gets the project's `.env` files that git ignores, copied once
  when it is created and never overwritten. A `.worktreeinclude` at the
  project's root (the file Conductor and Claude Code read) picks other files.
- The port shows under the composer, beside the branch. Click it to open
  `localhost` on that port in the built-in browser.
- The task's agent knows its ports. If it decides to start a dev server, or
  Metro in an iOS app, it uses the task's port instead of 3000 or 8081. DCC
  never starts or installs anything on its own.
- Creating a task costs nothing more: the ports are taken the first time the
  task needs them, and given back when it is deleted.
- Help has a new "Ports and .env per task" topic with examples for Next, Vite,
  Expo and Metro.

## One simulator per task

- The Device panel follows the task on screen to its own simulator. Another
  task's simulator keeps running, with its app and Metro, and reads "in use by
  <task>" in the list.
- An agent never takes a simulator another task holds, nor the one you are
  using in the task you have open.
- Closing the panel, or finishing a task, shuts down the simulators DCC
  started. One you opened from Xcode keeps running.

## Fixes

- An agent's text that resumes after a command starts a new paragraph instead
  of running into the sentence before it, in past conversations too, and in
  Cursor's replies.
- Cursor's agents get the task's variables on every turn.
- A long tooltip wraps inside its bubble instead of running past the window.
- A local-direct task follows a branch its own agent created during a turn,
  so the next message is no longer refused and the old-branch warning goes
  away.
- Coming back to a task's simulator shows "Starting…" until its screen
  arrives, never an empty black screen.
