# v0.1.38 Release Notes

## Provider Approval Controls

- Choose how agent actions should be approved directly from the composer:
  **Request approval**, **Approve for me**, or **Full access**.
- Claude Code, Codex, and Gemini translate the same DCC policy into their
  provider-native permission mechanisms, keeping the experience consistent
  without pretending the providers behave identically.
- The selected policy is remembered per workspace and provider, so switching
  models or tasks does not silently reuse an unrelated permission decision.
- Queued turns, follow-up turns, and programmatic session flows preserve the
  selected policy instead of falling back to an implicit provider default.

## Safety Boundaries

- Enabling **Full access** requires an explicit confirmation that explains the
  broader filesystem, command, credential, and network exposure.
- Protected worktrees continue to isolate Git checkouts, while the UI clearly
  warns that a worktree is not a security sandbox for the rest of the machine.
- Plan mode always forces the provider's read-only behavior, even when Full
  access is the saved execution preference.
- DCC-managed MCP tool policies remain enforced under provider bypass modes;
  Full access does not silently override tools configured as Ask or Deny.

## Provider Reliability

- Claude Code permission requests now flow through DCC's normalized approval
  policy, removing repetitive prompts when the user intentionally chooses a
  more permissive mode.
- Codex approval requests for commands, file changes, and scoped permissions
  are mapped to the selected policy while preserving explicit risk boundaries.
- Gemini uses its native approval modes for plan, automatic, and unrestricted
  execution.
- The provider catalog command is now registered in the desktop runtime, and
  the bundled fallback catalog exposes the same approval capabilities during
  startup. This prevents supported providers from appearing incorrectly as
  “Managed” with no selectable policy.

## Validation Before Publishing

- Run desktop type checks:
  `yarn workspace @dcc/desktop typecheck`
- Run the complete desktop test suite:
  `yarn workspace @dcc/desktop test`
- Build the production desktop frontend:
  `yarn workspace @dcc/desktop build`
- Run the sidecar test suite:
  `node --test sidecar/src/*.test.mjs`
- Run the Rust workspace tests:
  `cargo test --workspace`
- Check the Tauri crate:
  `cargo check --manifest-path src-tauri/Cargo.toml`
- Confirm release metadata is `0.1.38` in `package.json`,
  `sidecar/package.json`, `sidecar/src/index.mjs`, `src-tauri/Cargo.toml`, and
  `src-tauri/tauri.conf.json`.
- Let the release workflow build, sign, and package Linux and macOS artifacts;
  review every draft asset and `latest.json` before publishing.
