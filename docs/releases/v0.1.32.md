# v0.1.32 Release Notes

## Highlights

- Rebalanced the workspace rail so the workspace name is the brightest thing in
  its row, instead of the only neutral element among five colored ones.
- Activity color now marks the states that want the user — a finished run to
  review, a failed one to fix — while a running agent is carried by its pulsing
  dot.
- The recap line under each name is graded by value rather than hue, so the
  attention tone is the one that pulls the eye.
- Project headers read as section labels, letting the workspaces grouped beneath
  them read as the content.

## Rail Row Hierarchy

- The workspace name renders at full foreground weight in every row, selected or
  not. It previously inherited a dimmed row color, which left it quieter than
  the metadata around it.
- The activity label is tinted for `completed` and `aborted` runs only. An
  `active` run keeps a neutral label because the pulsing dot already reports
  that the agent is live, and no other element in the row animates.
- Elapsed time stays neutral in every state. It is metadata regardless of what
  the agent is doing, and coloring the duration doubled the tinted area without
  adding information.
- The bundle count badge dropped its cyan fill for a neutral one. It reports a
  count, not a status.

## Recap Tones

- The recap line keeps color for the `attention` tone alone, where something is
  blocking the branch. `ready`, `working`, `neutral`, and `done` now step down
  in neutral weight instead of each carrying a separate hue.
- Five tinted lines in a list read as a rainbow, which is what made a genuine
  attention state indistinguishable from a settled one.

## Branch Glyph and Project Headers

- The `merged` branch tone, which resolves from `status === "ready"` and so
  appears on nearly every healthy workspace, is pulled back to a tint. The
  transitional tones for `initializing` and `setup_pending` keep full chroma,
  where the glyph is reporting something in motion.
- Project group headers step down to 11.5px in muted foreground, brightening on
  hover. At 13px semibold they matched the weight of the workspace names below
  them, so the group and its children competed.
- The row count next to a project header is a plain tabular number rather than a
  pill, removing a shape from the header line.

## Known Gaps

- The grouping of workspaces under a project is still expressed only by the
  header and indentation. A connecting hairline between a header and its rows
  was considered and left out, since it costs horizontal space in a narrow rail.
- The rail was validated through type checks, unit tests, and builds rather than
  an interactive pass.

## Validation Before Publishing

- Run desktop type checks: `yarn workspace @dcc/desktop typecheck`
- Run the complete desktop test suite: `yarn workspace @dcc/desktop test`
- Build the desktop application: `yarn workspace @dcc/desktop build`
- Build the mobile web application: `yarn workspace @dcc/mobile-web build`
- Run the Rust workspace tests: `cargo test --workspace`
- Check the Tauri crate: `cargo check --manifest-path src-tauri/Cargo.toml`
- Confirm release metadata is `0.1.32` in `package.json`,
  `sidecar/package.json`, `sidecar/src/index.mjs`, `src-tauri/Cargo.toml`, and
  `src-tauri/tauri.conf.json`.
