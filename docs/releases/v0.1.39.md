# v0.1.39 Release Notes

## Composer Execution Controls

- Choose the provider and model from one compact composer menu, with search
  across the complete provider catalog.
- Configure reasoning effort and response style without crowding the composer
  footer.
- Cursor keeps Auto as the primary choice while exposing its additional models
  through an intentional advanced section.
- Supported Codex accounts surface their current usage window alongside the
  execution settings.
- Model, effort, planning, and approval controls now share a clearer visual
  hierarchy across compact application widths.

## Clearer Agent Responses

- Standard is now the default response style, allowing agents to explain enough
  for users to follow the result without changing execution effort or tools.
- The response-style preference is remembered globally across projects,
  worktrees, providers, and models.
- Direct remains available for concise replies and now preserves the same
  outcome-first, scannable organization as Standard.
- Codex, Claude, Gemini, Cursor, Droid, and Grok receive a normalized response
  intent while retaining their provider-native execution behavior.

## Reading and Visual Hierarchy

- Long replies use clearer Markdown sections with more distinct headings and
  deliberate spacing between titles, paragraphs, lists, and code.
- Both response styles encourage short descriptive headings only when a reply
  spans distinct topics, avoiding unnecessary formatting in simple answers.
- These presentation instructions apply only to the final assistant reply;
  MCP access, tools, reasoning effort, implementation behavior, and approval
  boundaries remain unchanged.

## Validation Before Publishing

- Run desktop type checks:
  `yarn workspace @dcc/desktop typecheck`
- Run the complete desktop test suite:
  `yarn workspace @dcc/desktop test`
- Run the Claude sidecar test suite:
  `yarn --cwd sidecar test`
- Run focused core and Codex provider tests:
  `cargo test -p dcc-core agent_turn_prompt` and
  `cargo test -p dcc-providers codex_app_server`
- Check Rust formatting:
  `cargo fmt --all -- --check`
- Confirm release metadata is `0.1.39` in `package.json`,
  `sidecar/package.json`, `sidecar/src/index.mjs`, `src-tauri/Cargo.toml`, and
  `src-tauri/tauri.conf.json`.
- Let the release workflow build, sign, and package Linux and macOS artifacts;
  review every draft asset and `latest.json` before publishing.
