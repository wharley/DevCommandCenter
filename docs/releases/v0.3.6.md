# v0.3.6 Release Notes

## Delivery

- The changes column shows where a task's work is on its way to production,
  as one rail: Commit → Enviado → PR → Checks → Revisão → Merge. Done steps are
  green, the current one amber, a stopped one red, with a line saying where
  things stand beside the next step's button.
- The rail's pull request step opens it in the browser; its Checks step lists
  the checks on GitHub: the failed and running ones by name, the ones that
  passed in one line.
- Changes open as a compact row per file (a click opens the diff on the
  stage). The tree and the cards with the diff inside are one click away on
  the same button.
- One strip holds the scopes (Workspace, Último turno, Branch), the totals
  and the layout button.
- A push the before-push checks stop opens their report, with "Pedir ao
  agente para corrigir".
- "Criar PR" always opens its dialog, and confirming a merge is no longer
  red.

## Pull requests

- The list reads in sections, nearest to production first: "Você aprovou",
  "Aguardando o autor", "Precisa de você" and "Rascunhos" under Revisando;
  "Prontos para mesclar" first under your own. Each section folds.
- A row says its state in one icon (draft, failing checks, checks running,
  your review waiting on the author, approved), then the title and
  "repo #n · author · age". Each filter shows how many it holds.
- The list opens at once with what it showed last, and refreshes behind it.
- A pull request's detail has the same rail (Aberto → Checks → Revisão →
  Merge), who reviewed with their decision and when, and its checks summed
  up.
- The filled button follows the next step: "Revisar" when the pull request
  waits on you, "Mesclar" on your own when nothing is in the way.
- Approve or request changes from the summary, without opening the code. The
  send button says what it sends.
- "Escrever | Prévia" shows your review as GitHub will render it; the pull
  request's files in it are chips that open that file's diff.
- Reviews sent with text show in the activity with the comments, newest
  first.
- When some projects do not answer, the warning names them and the cause.

## Agents and rooms

- The team room reads lighter: news from sources in one line you open, long
  answers folded to their opening, and "2 trabalhando · 1 esperando você"
  beside the title.
- The room has the conversation's trail down its left margin: a tick per
  message of yours, its answer on hover, a click to go there.
- Links in your messages read as in the task's chat, and agents as pills.
- A task opens on its own agent's conversation, not on the Reviewer's, and
  the Reviewer called in a task runs on its own account.
- An agent no longer reviews a pull request that was already merged or
  closed.

## Computer use

- On the Mac an agent clicks and types in an app without taking your mouse
  or bringing its window forward. The agent's cursor shows on the screen, the
  floating preview shows what it sees, and "Encerrar acesso" stops it.
- Computer use works on Linux.

## Conversation

- A one-line shell command in an answer has ▶: a click runs it in a new tab
  of the task's terminal. Nothing runs without the click.
- "Objetivo" starts the agent's own `/goal` (Claude, Codex, Cursor, Grok).
  DCC's own objective is gone.
- A message sent while the agent works reads where it was sent.

## Usage

- DCC Usage reads the Claude Code and Codex logs on this machine, inside and
  outside DCC: tokens, estimated cost, calls and sessions by day, model,
  project and agent, with a heatmap of when you work. A model without a known
  price is listed apart, never counted as zero.

## Linux

- "Atualizar" for the provider CLIs finds where each one is installed and
  updates it there.

## Fixes

- A pull request whose checks still run is no longer shown ready to merge.
- A long file path no longer pushes a row's counts and actions off the
  changes column.
- Hovering the room's trail no longer rebuilds the whole room.
