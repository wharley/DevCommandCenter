# v0.3.5 Release Notes

## Agents

- "Agentes" in the sidebar opens your team: a team room where you write once
  and DCC picks who answers (or you call someone with `@`), a room per
  project that knows its project, and each agent's own conversation.
- Each agent has a role, its own model and account, the projects it works
  in, a memory it keeps per project, and its own mascot.
- Agents open tasks in your projects from their conversation; the task shows
  whose it is, runs in its own worktree and reports back once.
- Agents can pass work to a teammate: they suggest it and you decide, or they
  pass it themselves to the teammates you allowed.
- Sources: an agent watches your connectors (Slack mentions, tasks assigned
  to you) with no model, and wakes only with what is new.
- An agent proposes the reply it found ("resposta pronta"): you read it, edit
  it if you want, and send it with one click. Nothing leaves before that.
- Routines (days and a time), a monthly token limit per agent, "Pausar
  agentes", and what each agent may use (DCC's tools and each connector).
- The Reviewer can wake on its own: when a pull request you reviewed is
  updated, when a task's CI fails, when reviews come on a task's pull
  request. All off by default.
- Check-ins with no model: pull requests asking for your review, issues
  assigned to you and stalled tasks show as cards; a pull request opens in
  DCC's Pull Requests, with GitHub beside it.
- The room shows agents at work live, their questions and approvals as cards,
  what each task changed and where its delivery stands, and tells you when an
  agent needs you.
- Build an agent by talking, start from a template, or duplicate one (another
  Dev on a different model, say).
- Agents read GitHub through DCC (pull requests, checks, reviews, deploys)
  with the `gh` you are signed into; it never writes.

## Pull requests

- The Reviewer decides first: approve, request changes, or what is missing to
  decide, and does not repeat what an earlier review already said.
- It suggests code when it is worth it: a GitHub suggestion you apply with one
  click, or an example to copy. Comments can cover several lines.
- Review comments read as their content: markdown, with their severity as a
  chip.

## Phone

- Rooms first: the home opens on your rooms, with the desktop's cards,
  reactions, approvals, questions, live work and the replies to send.
- Links in answers read by their label, and mentions show as pills.

## Fixes

- A code block inside the Reviewer's summary no longer cuts its answer.
- A check still running is no longer shown as failing.
- The phone's room no longer blinks, and its last message stays above the
  field.
