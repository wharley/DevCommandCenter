# v0.1.37 Release Notes

## Pull Request Center

- Pull requests now have a dedicated workspace in the sidebar, with views for
  all requests, requests awaiting your review, and requests created by you.
- Review summaries bring together description, checks, activity, comments, and
  code without requiring every pull request to become a DCC task.
- Publish general comments, reply to discussions, add inline diff comments,
  approve, or request changes from the same review surface.
- Ask an agent to prepare a review or response while keeping publication under
  explicit user control.
- Open the pull request in its forge or create an isolated task directly from
  the selected pull request when implementation work is needed.

## Protected Tasks and Project Identity

- New tasks use isolated worktrees while clearly showing the protected base,
  active project, branch, and change state above the composer.
- Project setup is now recommended instead of running automatically. The Dock
  exposes the detected command and lets the user execute or skip it.
- Projects support a display name, icon, color, default base branch, and setup
  preference while preserving the real repository identity.
- Projects and tasks can be pinned without creating duplicate sidebar sections.
- Automatic task titles now stay synchronized between the composer and sidebar,
  preventing generic names from leaking into checkpoint commits and pull
  requests.

## Composer and Agent Workflow

- Conversation startup is faster and more reliable, including immediate focus
  in the prompt field and durable composer attachments.
- Delegation is consolidated in the composer and supports intentional agent
  follow-ups without competing controls in the header.
- Plan review and conversation recovery flows are clearer, including safe
  recovery when an active provider conversation becomes invalid.
- Workspace context is surfaced where it is useful and inactive directory
  controls have been removed from the composer.

## Terminal, Inspector, and Polish

- The terminal is task-aware and opens with clearer project and worktree
  context.
- The Inspector now reacts to the active workflow: it stays available for the
  next delivery step after a commit and closes when an operation is complete.
- Update availability moved to the sidebar, where it remains discoverable
  without occupying the composer header.
- Sidebar hover details use the configured project identity, task deletion
  dialogs stay contained on smaller windows, and the execution Dock uses a
  quieter neutral surface while retaining semantic status colors.
- The alternate-folder project flow and workspace completion after merge have
  been restored and hardened.

## Validation Before Publishing

- Run desktop type checks:
  `yarn workspace @dcc/desktop typecheck`
- Run the complete desktop test suite:
  `yarn workspace @dcc/desktop test`
- Build the production desktop frontend:
  `yarn workspace @dcc/desktop build`
- Run the Rust workspace tests:
  `cargo test --workspace`
- Check the Tauri crate:
  `cargo check --manifest-path src-tauri/Cargo.toml`
- Confirm release metadata is `0.1.37` in `package.json`,
  `sidecar/package.json`, `sidecar/src/index.mjs`, `src-tauri/Cargo.toml`, and
  `src-tauri/tauri.conf.json`.
- Let the release workflow build, sign, and package Linux and macOS artifacts;
  review every draft asset and `latest.json` before publishing.
