# v0.1.94 Release Notes

## Usage limits are a wait, not an error

- When Claude or Codex runs out of the plan's usage limit mid-task, the task
  no longer ends as "interrupted". It shows "Aguardando limite · volta às
  03:40" (violet, outside "Precisa de você") in the sidebar and above the
  queue, the timeline shows a quiet notice instead of the red error, and
  queued messages wait with the task.
- Without a known reset time DCC does not guess: the task shows "Pausado por
  limite" under "Precisa de você", on the desktop and on the phone, with one
  push notification and a "Tentar de novo" action.
- The limit does not count as a failure of the task's objective.
- Detected from Claude's rate-limit events and Codex's `usageLimitExceeded`
  error with its rate-limit snapshot. Other providers keep showing limits as
  ordinary errors.

## Continue on its own when the limit runs out (opt-in)

- Off by default. Turn it on for new tasks in Settings → General, per task
  with the hourglass in the composer, or in the phone's new task.
- After the reset plus 1–3 random minutes, DCC sends the fixed message
  "Continue de onde parou." with the task's same access level, then the queue
  moves on as usual. At most 3 automatic resumes per task every 12 hours;
  after that the task waits for you.
- Survives an app restart: a reset that passed while DCC was closed resumes
  right away.
- Never spends a paid Codex reset credit.
- "Manter o Mac acordado → Durante agentes" now holds the Mac until the
  resume; with keep-awake off, DCC warns and offers to turn it on.

## Computer use

- Clicks, scrolling and typing work reliably in web content (Chromium,
  Electron) and native apps: captures list the window's accessibility
  elements, clicks fall back to real pointer input at the element's visible
  center after checking nothing covers it, and editable elements get
  `set_value`.

## Validation

- All 1136 frontend tests passed; desktop and mobile TypeScript checks passed.
- Rust workspace tests passed except the three known `dcc-mcp-fixture`
  failures, unrelated to this release.
- End-to-end on a desktop with a temporary database and a fake Codex that hits
  the limit with a short reset: waiting state, keep-awake assertion
  (`pmset -g assertions`), live automatic resume within the slack, resume
  after restart with the queue dispatched, and "Pausado por limite" resumed
  from the phone API.
