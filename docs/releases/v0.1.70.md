# v0.1.70 Release Notes

## Prevent notes from entering the wrong project conversation

- Fix a project context isolation bug: opening a note from the library while a
  task in another project was selected could allow that note's content and saved
  context to be added to the unrelated conversation.
- Disable "Add to current conversation" unless the selected task belongs to the
  note's project. Show an explanation naming the project and suggesting selecting
  a task there or creating a task from the note.
- Check the destination again after saving the note, preventing insertion if the
  project, task, or conversation changes while the save is pending.
- Keep notes available for viewing and editing across projects. Creating a task
  from a note continues to use the note's linked project.
- Include the explanation in Portuguese and English, with an accessible
  description associated with the disabled action.

## Validation

- All 738 desktop tests passed, including regression coverage for opening notes
  from another project, missing tasks, same-project insertion, task creation,
  and destination changes during saving.
- Desktop TypeScript checking, the production frontend build, and workspace-wide
  `cargo check` passed.
- Signed release artifacts remain subject to CI verification and installed-app
  validation before publication.

## Updating

Use the in-app updater after publication, or download the package for your platform.
Existing projects, conversations, and notes remain in place; a clean installation
is not required. This fix prevents new cross-project insertions; it does not remove
note content previously added to conversations.
