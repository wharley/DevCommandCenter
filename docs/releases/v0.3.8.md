# v0.3.8 Release Notes

## Pull requests, to the merge

- The merge dialog says what a pull request still waits on before the forge
  refuses: checks running, required checks failing, the approval missing,
  changes requested, the branch behind its base.
- "Mesclar quando estiver pronto": where the repository allows auto-merge,
  GitHub merges the pull request once that clears. In place of "Mesclar" the
  pull request then shows it, with "Cancelar".
- "Apagar o branch depois do merge", in the dialog. Only the repository's own
  branch, never a fork's, never your local checkout.
- A "⋯" menu on a GitHub pull request: "Atualizar com a base" when its branch
  is behind, "Fechar pull request" (with an optional comment), and on one
  just closed "Reabrir" and "Apagar o branch". Each asks first.
- Checks: each one that is failing or running opens its page; a failed GitHub
  Actions job shows what failed (the failing step) and can be run again.
- A review being written is not lost: its line comments, text and decision
  come back when you return to the pull request, also after a restart.
- A line comment can take in the lines above it, and "Sugerir" writes the
  suggestion block for you to edit.
- "Visto" on each file, with how many were seen and "Esconder vistos". The
  marks are this computer's.
- A file named in a pull request's activity is a chip that opens it in
  "Código" (the summary used to show none).

## Merge conflicts

- The conflicted file takes the screen. There is one editor, the file itself:
  each block is tinted where it is, your lines then the incoming ones, with
  "Aceitar o seu", "Aceitar a base" and "Aceitar ambos" on its first line.
  What is left is edited like any text, also after accepting a side.
- The marker lines read as whose side starts there instead of `<<<<<<<` and
  `=======`; they show their own text again while the caret is on them.
- One bar on top: the file, "arquivo N de M" to go to another, the blocks'
  position with arrows that bring the block into view, the agent, "Comparar"
  (beside the editor, never in its place) and a "⋯" with what is rarely
  asked: take a whole side, restore, delete the result.
- "Resolver com agente" no longer starts a conversation in the task. It is
  one read-only run in the checkout that can be stopped. The agent reads the
  whole file and answers what replaces each block; the answer goes into the
  file with each block tinted, the conflict it replaced in red above it, and
  "Recusar" and "Aceitar" on its first line. Refusing puts that block's
  conflict back; editing a block makes it yours.
- "Resolver todos os arquivos com agente", with two or more conflicted files:
  one file after the other; each answer shows when its file opens.
- "Resolver" on a conflict only the forge reports now brings the base in and
  shows the conflicts, instead of a screen to start the merge.
- Updating with the base that leaves conflicts opens the resolver instead of
  an error.
- "Recomeçar com a base atual" and "Abortar merge" in a menu in the header:
  a merge under way that is not the one to resolve can be dropped for the
  current base in one step.
