# v0.1.87 Release Notes

## Reviewer follow-up rounds

- Fix review loops: calling the Reviewer again in a task used to open a new
  conversation that reviewed from scratch and raised new minor findings on the
  code written to answer the previous ones.
- Keep one Reviewer conversation per task. From the second call on, the request
  lists the findings of the earlier round and the Reviewer says what happened
  to each one, reads only what changed, and raises something new in a fix only
  when it is critical or major.
- Scope findings to the change and to inputs that can actually arrive. Code the
  change did not touch and scenarios the Reviewer could not confirm are no
  longer findings. This also applies to pull request reviews.
- Show on the findings card how many findings block the commit: critical and
  major findings block, minor ones are optional.
- Replace "Send all to the author" with "Send blocking findings". Minor
  findings are still sent one at a time.
- End the fix request to the author by asking for the smallest change, without
  extra validation, defensive layers or refactoring.
- Keep the review and its diff markings when you ask the Reviewer a question
  after it.
