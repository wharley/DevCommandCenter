# v0.1.88 Release Notes

## Delegation from the chat

- Delegate by asking in the chat. The composer's delegate button is gone: the
  agent calls DCC's own `dcc_delegate_task` tool, and the whole run (isolated
  worktree for implementation, child conversation, durable record) is owned by
  the backend, so a reload no longer strands a delegation.
- Hand the result back to the agent that asked, as a `[DCC]` message. When the
  parent is still working, the result is steered into its open turn on
  providers that support it, and queued for after the turn otherwise.
- Add blocking waits (`wait=true` and `dcc_task_wait`) for when the agent
  cannot continue without the result. Delivery is exactly once.
- Never run a delegated child above its parent. Review and explain run truly
  read-only on Claude and Codex, enforced by the runtime instead of the prompt.
- Let a watchdog settle children that ended unobserved, never started or ran
  past their timeout (15 min read-only, 30 min implement).
- Add a lineage menu in the chat header with each delegation's status, open
  and cancel, and a link back to the asking conversation from a child. The
  session history nests children under their parent.
- Let the agent name the task with a short title, shown as the child
  conversation's title instead of "Delegated implement: …".
- Fix every agent delegation failing with "workspace not found".

## Delegation in the parent conversation

- Show the `[DCC]` hand-back as a one-line system event; the text written for
  the agent stays one click away.
- Place the delegation card after the reply of the turn that delegated, with
  the task's title and the child's robot walking while it works.
- Render the child's report as Markdown, collapsed to its first lines.
- List changed files as chips that open their diff in the parent's Inspector.
- Show the build and test commands the parent agent ran on the result
  ("Checked in this conversation").
- Offer edits awaiting review where you are: a strip at the end of the
  conversation and a banner in the parent's Changes view, so the child
  conversation no longer has to be opened to see them.
- Say "Awaiting your review" in amber in the sidebar instead of "Completed",
  and "delegated 1 task" in the turn summary.

## Conversation

- Show what each tool did: command, output, exit code and edit diff, for
  Claude, Codex, Cursor, Droid, Gemini and ACP providers.
- Stream the agent's narration as it is written, one line per burst of work,
  and fold a finished turn into "Worked for 1m 12s · edited 2 files, ran 3
  commands". Turns end with their duration and token usage.
- Edit from here: the pencil on a message rewinds the conversation, the
  agent's native conversation and, when you choose, the files (by Guarded
  Undo), including a file several removed turns changed.
- Steer Claude's active turn: guidance sent while it works is folded in at its
  next tool boundary.
- Resume the native Claude and Codex conversations after the runtime
  restarts.
- Keep DCC's context out of your words in Codex's native history (codex-cli
  0.135.0+).
- Send referenced images as native image input and show their thumbnails in
  your message.
- Pin the turn you send near the top and keep the live status, with the
  agent's robot, in sight while the reply grows.
- Show a pixel robot per provider in the timeline: it walks while the agent
  works and waves in amber when it needs you.

## Sidebar and projects

- Replace "Running" with "Needs you": tasks waiting on you, unread results,
  merge conflicts, failing checks and delegated edits awaiting review, ordered
  by when each one came back.
- Split projects into Pinned and Recent once a project is pinned.
- Snooze a task for an hour, until tomorrow or until Monday.
- Give each project a Brazilian-fauna pixel-art mascot by default, or upload a
  logo. The mobile companion shows the same mascot.
- Free up space from completed tasks in one go; only committed and pushed
  tasks come checked.

## Agents

- Add the Researcher's idea flow.
- Add the Reporter: a recap of what moved in your tasks since the last one,
  built from the database without a model. It walks to the composer when
  there is news, and warns when completed tasks take more than the limit you
  set (5 GB by default).
- Split the in-app help into one topic per DCC agent.

## Inspector and settings

- Send failing GitHub checks to the task's agent, with the failing step of up
  to three Actions logs.
- Keep code-change requests out of the Reviewer's conversation.
- Follow the system appearance (Light / Dark / System), including on Linux.
