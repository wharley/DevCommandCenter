# v0.1.86 Release Notes

## DCC agents and Reviewer

- Introduce DCC's built-in agents with the Reviewer, a dedicated agent that
  offers to review task changes and runs when you accept or call it manually.
- Show review findings by severity with file and line links, mark findings on
  diffs, and draft requests to send one finding or all findings to the author
  agent. Mark reviews as outdated after the author runs another turn.
- Review pull requests from the hub and turn findings into editable draft
  comments. Reviews keep running when you navigate away; comments are only
  published when you submit the review.
- Add an Agents sidebar section and a Reviewer page with activity, review
  history, and a result-ready state that remains until you open the result.
- Customize the Reviewer's name, mascot, extra instructions, and review offers;
  select provider, model, and reasoning effort from a single menu.
- Fix review offer targeting, pull request navigation, editor draft resets,
  finding parsing, and cleanup after a failed agent session binding.

## Chat code blocks

- Use one syntax-highlighted code block presentation in prompts and replies,
  sharing the diff viewer's themes and showing line numbers only when the
  source provides a starting line.
- Format raw pasted JSON in prompts and collapse code blocks taller than
  20 lines.

## Memory, skills, and model routing

- Include conversation context when deciding which memories and skills fit a
  task, and rank relevant memories to keep the best three above the threshold.
- Compare the complete model catalog to choose an appropriately sized model,
  preserving explicit preferences and favoring capability when difficulty is
  unclear.
- Version the decision policy as `jev-v3` so its evaluations stay separate from
  the previous policy.

## Task state and documentation

- Keep tasks without their own worktree open when the project branch has an
  older merged change request, and ignore those merged requests in the main
  checkout's status.
- Document DCC agents, the Reviewer workflow and mascot, and the updated
  decision policy; update the README with agent documentation and the project
  activity badge.

## Validation

- GitHub Actions release workflow builds the Linux and macOS artifacts.
- 51 frontend tests passed across agents, code presentation, user messages,
  Inspector task state, and diff navigation.
- Desktop TypeScript checks passed.
- All seven release version references match `0.1.86`.
- `git diff --check` passed.
