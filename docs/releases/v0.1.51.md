# v0.1.51 Release Notes

## Native Codex orchestration

- Add guarded support for the compatible Codex multi-agent runtime while
  preserving the previous behavior when the installed CLI lacks the required
  capability.
- Add a project-level `dcc-orchestration` preset that helps GPT-5.6 Sol split
  independent work across a small team of Terra subagents and integrate their
  results.
- Add a per-session concurrent-subagent setting under provider configuration,
  including an Automatic mode that leaves the decision to Codex.
- Validate the authenticated Sol-to-Terra workflow end to end without deriving
  completion from rollout evidence.

## Agent tree and supervision

- Show native Codex subagents in a hierarchical agent tree while preserving the
  existing standalone cards for activity that does not report a path.
- Display the primary Sol agent separately from its children and reconcile
  sparse lifecycle events by native thread identity.
- Add controls to instruct or interrupt active subagents when the negotiated
  Codex runtime supports those operations.
- Persist exact Completed and Failed terminal states for new activity and show
  the neutral Ended state for historical sessions that lack a final child
  event.

## Clickable code references

- Open workspace file links from assistant messages directly in the DCC Code
  Dock instead of forwarding them to the operating system.
- Support relative paths, absolute paths inside the active workspace,
  `file://` links, `path:line:column`, and GitHub-style `#LxCy` positions.
- Focus the requested line and column in existing or new editor tabs while
  rejecting traversal, external URLs, and absolute paths outside the workspace.
- Add localized hover guidance so file references clearly describe the action
  before the user clicks.

## Documentation

- Add an end-user Codex orchestration guide covering preset installation,
  automatic and explicit activation, concurrency, the agent tree, supervision,
  troubleshooting, and a safe Sol-to-Terra test flow.

## Validation before publishing

- Run desktop type checks, the complete desktop test suite, and the production
  desktop build.
- Run Rust formatting, workspace checks, and the complete Rust test suite.
- Run the authenticated Codex Sol-to-Terra smoke test against the production
  adapter.
- Confirm release metadata is `0.1.51` in the root package, sidecar, Cargo, lock,
  and Tauri configuration files.
- Let the release workflow build signed macOS and Linux artifacts, inspect the
  draft release and `latest.json`, then publish only after manual verification.
